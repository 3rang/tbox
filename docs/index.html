Telegram from the command line, in plain C.

tbox is a small, readable Telegram client built on TDLib. Log in by scanning a QR code, send a message, upload a file, get notified of new ones. Five commands, about 1,100 lines of C — meant to be read as much as run.

Five commands

A chat is me (Saved Messages), @username, or the chat id that watch prints. Nothing else to learn.

tbox login

Scan a QR code with the Telegram app. Asks your two-step password if you have one. Once.

$ tbox login

tbox send

Send a text message. Waits until Telegram confirms it.

$ tbox send @alice hello there

tbox upload

Send a file as a document, with progress. me drops it into Saved Messages.

$ tbox upload me backup.tar.gz "weekly"

tbox watch

Print new incoming messages as they arrive — from every chat, or one.

$ tbox watch @alice

tbox logout

End the session on Telegram's side and delete the local database.

$ tbox logout

How it works

TDLib does the hard parts — MTProto, encryption, the local database. Its C interface is four functions and every byte through them is JSON. tbox is organised along that line.

  1. Opensession_open() reads TBOX_API_ID/TBOX_API_HASH, creates a TDLib client and runs the login state machine. With a saved session that is one setTdlibParameters and TDLib answers authorizationStateReady.
  2. RequestThe command sends its requests — sendMessage, getChat — and waits for the updates it cares about, such as updateMessageSendSucceeded or updateNewMessage.
  3. Closesession_close() sends close and waits for authorizationStateClosed, so TDLib flushes its database.

Set TBOX_DEBUG=1 to watch the JSON go by (secrets blanked) — the quickest way to learn the TDLib API.

src/
  main.c           command table
  core/
    td.c           four TDLib calls; td_request() = post + wait for reply
    json.h         ten lines over cJSON: jstr, jint, jobj…
    config.c       ~/.tbox and the API credentials
    session.c      open / close around each command
    platform.c     the Windows/POSIX differences
  tg/
    auth.c         login state machine
    qr.c           draws the login link as a QR code
    chat.c         me / @username / id → chat
    message.c      message object → one line
    outbox.c       sendMessage + wait, upload progress
  cmd/           one file per command
tests/             a scripted fake TDLib, no network

Why C

Because it is the smallest honest way to show what talking to Telegram actually takes. No runtime, no framework: a few hundred lines you can read in an evening.

Why TDLib

It is Telegram's own client library. Linked at compile time — prebuilt by default, or compiled from source into one static binary with -DTBOX_TDLIB_FROM_SOURCE=ON.

Why QR login

The shortest flow TDLib offers: no phone number, no SMS code. TDLib hands over a tg://login link, tbox draws it, your phone confirms.

Why cJSON

TDLib's C API is JSON. Some parser is unavoidable; one MIT file is less code than writing it yourself.

Install

One archive per platform, with the TDLib runtime inside. Unpack and run. Telegram requires an api_id and api_hash for every client app — put yours in the environment first.

# Linux / macOS
export TBOX_API_ID=12345 TBOX_API_HASH=0123456789abcdef…
v=1.0.0; a=linux-x64   # or linux-arm64, osx-arm64, osx-x64
curl -L https://github.com/3rang/tbox/releases/download/v$v/tbox-$v-$a.tar.gz | tar xz
./tbox-$v-$a/bin/tbox login

macOS may quarantine the download: xattr -dr com.apple.quarantine tbox-*

# Windows (PowerShell)
$env:TBOX_API_ID = "12345"; $env:TBOX_API_HASH = "0123456789abcdef…"
Expand-Archive tbox-1.0.0-win-x64.zip
.\tbox-1.0.0-win-x64\bin\tbox.exe login

Get the zip from the releases page.

# From source (CMake 3.18+, any C11 compiler)
git clone https://github.com/3rang/tbox && cd tbox
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build && ctest --test-dir build
./build/tbox login

CMake downloads the pinned TDLib for your OS, sha256-checked.
